# A sample AI-written proposal (Nov 11 2026)

Adam compared the RFI Builder's download with a draft from Adobe's own tool for the same RFP (Washington State DSHS, RFP
2123-778): theirs reads like a proposal, ours like a list of answers. "Let's do it better and let's make it look so much
better as well. I am 100% OK if it is 100% generated by AI."

This folder is a sample, to judge before anything in the tool changes.

- `Proposal_RFP_2123-778_AEM_Forms_Implementation.docx` (and `.pdf`): 25 pages, 12 sections, a 67-row requirements
  matrix, 26 catalog services with planning hours (1,360 at Typical), 29 Adobe sources.
- `content.json`: the proposal as written by an AI model (a helper model in the session, standing in for what the tool
  would send to its reader) from three inputs: the RFP's text, the list of what it asks for, and `catalog_pack.json`.
- `catalog_pack.json`: the tool's own catalog for the products this RFP needs (services, scopes, hours, the Adobe page
  each rests on, and sentences already checked against Adobe's pages).
- `build_docx.js`: lays `content.json` out as the Word document (`node sow/proposal_sample/build_docx.js content.json out.docx`).

Checked by script: every source is a page in the catalog pack; every hour figure in the services table equals the
catalog's; no em or en dashes; none of the words Adam ruled out.

What the writer could not ground in the catalog is stated in the proposal as custom work or "Confirm with Adobe": the
RFP's Adobe Managed Services and FedRAMP hosting (the catalog describes AEM Forms as a Cloud Service), Interactive
Communications and the Agent UI, watched folders, legacy Central Pro and XFT conversion tooling, barcodes and mail,
Secure Access Washington sign-in, the forms-history search front end, and DITA and Workbench training.
