### 1. Ad platforms into CJA (Google Ads V2, Meta, Pinterest, Snapchat, TikTok; others through summary data) (partly right; add now)

- **What's true:** CJA alone can take ad platform data. Real-Time CDP is not needed. The Google Ads (V2), Pinterest, Snapchat and TikTok pages each say the source 'is available as part of the Customer Journey Analytics SKU'. Meta Ads has no SKU line, but its page names CJA as a consuming app, and the CJA product description lets customers 'configure non-Adobe sources'. Only the Advanced Enterprise list is excluded, and no ad source is on that list. The item is wrong to say there is 'no license hurdle', though. Adobe's guide for joining paid media data to web data requires 'Customer Journey Analytics Select or higher', because the join uses derived fields, and Foundation has 'Derived Fields: Not included'. The Nov 4 skeptic's fix 6 got the reason wrong. These sources write lookup datasets plus a summary-metrics dataset, not event datasets, so Foundation's one-event-dataset limit is not what blocks them. The join is aggregate only: it 'does not link an ad impression or click to an individual person'. Status today: Google Ads V2 has no beta label. The old Google Ads page (/advertising/ads) is still beta, one-time ingestion only, and the sources home page still links to it. Pinterest, Snapchat and TikTok are beta. Meta has no beta label. All five are Azure-only on the sources list, so confirm the client's Experience Platform runs on Azure, not AWS. The Content Analytics paid media channel is an alternative, but its Pinterest, Snapchat and TikTok support is Limited Testing, and Content Analytics is now sold only as a standalone product.
- **License:** Any CJA package can run the source connectors (Google Ads V2, Pinterest, Snapchat and TikTok are in the CJA SKU; Meta falls under the non-Adobe sources clause, so confirm). Joining the data to web conversions needs CJA Select, Prime or Ultimate. Real-Time CDP is not needed. The Content Analytics route needs a standalone Adobe Content Analytics license.
- **Availability:** Google Ads (V2): available, page updated Oct 21 2026; pick the card without the Beta label. Old Google Ads source: beta, UI one-time only. Meta Ads: no beta label. For Meta: a Meta app with Marketing API access and ads_read and ads_management scopes, plus a user with ad-account rights. ### 7. CRM to Marketo Engage and Target (partly right; add now)

- **What's true:** Both routes are documented on live Experience League pages today, and most of the mechanics hold up. Four things need fixing.

(1) Marketo has three native CRM connectors, not two: Salesforce, Microsoft Dynamics and Veeva CRM.
- Salesforce: leads, contacts and Salesforce campaigns sync both ways. Accounts, users, opportunities, custom objects and activity sync one way, from Salesforce to Marketo. It runs all day in cycles with a 5 minute pause.
- Dynamics: you install the Marketo Lead Management solution in Dynamics. Leads and contacts sync both ways; accounts, opportunities, users, teams and custom entities sync from Dynamics to Marketo. It runs in background batches, not in real time. MFA must be off for the sync, and sandbox refresh and instance copy are not supported.
- Veeva: only the contact fields on Person Accounts sync both ways. Leads, contacts, business accounts, opportunities, campaigns and activities are not synced.
- The biggest risk, missing from the recommendation: "After you sync Marketo to a CRM, you cannot perform a new sync without replacing the instance." The field mapping has to be right the first time.

(2) CRM to Target works through Customer Attributes, part of the Experience Cloud People service. The client exports a CSV keyed on the CRM customer ID, uploads it, validates the schema and subscribes the source to Target.
- Browser upload: up to 100 MB. FTP: up to 4 GB, at least 10 MB, one file every half hour, plus a .fin file.
- Target can use 5 attributes on Target Standard and 200 on Target Premium.
- The visitor must be identified on the site with a customer ID and the authenticated state, through setCustomerIDs (Experience Cloud ID Service) or a Namespace Code on the identityMap with the Web SDK.
- Customer Attributes needs its own product profile in the Admin Console. Creating or changing a source needs Audience Manager admin rights.

The other way in is the Target Bulk Profile Update API (v2 is current).
- It is an HTTP POST of a batch file keyed on thirdPartyId (mbox3rdPartyId) or pcId, never ECID.
- A file must be under 50 MB and 500,000 rows. Updates usually land within an hour but can take up to 24 hours.
- The data is usable only in Target, not shared with Analytics, and sending empty values does not clear old ones.

(3) The recommendation's caveats are confirmed:
- Adobe does not promise 100% onboarding (up to 0.1% of large batches may be lost).
- The default profile lifetime is 14 days.

(4) Correct the vendor line: Marketo syncs natively with Salesforce, Microsoft Dynamics and Veeva CRM.
- **License:** CRM + Marketo:
- Marketo Engage plus the client's own CRM, which must be Salesforce with API access for the sync user, Microsoft Dynamics 365 with the Marketo solution installed, or Veeva CRM.
- Adobe's page says only "You must have access to Salesforce API's". The claim that Salesforce Professional Edition lacks API access by default comes from Salesforce, not from Adobe, and I did not verify it.
- I did not check whether the CRM sync differs by Marketo package.

CRM + Target:
- Adobe Target (Standard allows 5 subscribed attributes, Premium 200) and access to Customer Attributes (a Customer Attributes product profile in the Admin Console, with users in the Customer Attributes group and a Target or Analytics group).
- Creating or changing a source needs admin rights in Audience Manager, per the upload page.
- The Bulk Profile Update API needs only Target.
- No Experience Platform, Real-Time CDP or CJA license is needed for either route. CJA is not part of this item.
- **Availability:** Neither route is labeled beta or limited on any page I opened.
- Marketo Salesforce, Dynamics and Veeva sync pages: all updated Oct 7 2026.
- Target Customer Attributes pages: updated May 12 2026. Experience Cloud Customer Attributes pages: Sep 16 and Oct 1 2026.
- Bulk Profile Update API: updated Oct 27 2026. v2 is current and v1 is still supported.

Limits stated on the pages:
- Dynamics: no sandbox refresh, no instance copy, MFA must be off.
- Any Marketo CRM sync is effectively one-time per instance.
- Customer Attributes is "designed to handle a few files per day".

The Customer Attributes upload page still says "Adobe Target at.js (any version) or mbox.js version 58 or later is required". The same page documents a Namespace Code for Web SDK identityMap use, so Web SDK support is documented but the prerequisite text is inconsistent.

Several older URLs return 404 today, but every source URL in the recommendation loads.
- **Partner work:** The partner work is real and billable. Adobe publishes no hours for either route.

CRM + Marketo:
- Adobe's own guide has the customer build a data dictionary with "input from the Marketing and Sales teams and your CRM Admin". It warns that duplicate fields can only be re-mapped through Adobe Customer Support.
- The setup steps must be done by a Salesforce or Dynamics administrator: profile, permissions, a dedicated sync user, field-level security, and the Marketo solution install and publish on Dynamics.
- Custom objects must be enabled one at a time, and the sync user needs read access.
- So the existing MK02 line (32 / 60 / 120, already in catalog.json) is the right line to put on the connection. The optional custom-object add-on (16 / 32 / 64) is our own estimate.
- The product does the ongoing sync itself, so there is no monthly partner line for the sync.

CRM + Target, all real work:
- Export from the CRM.
- Line up the customer ID with setCustomerIDs or the Web SDK identityMap namespace, and the authenticated state.
- Create the source, validate the schema and subscribe it to Target.
- Set up an FTP or API feed to Adobe's limits.
- Troubleshoot. Adobe says ID passing and republish problems cause most failures.

The recommendation's 16 / 32 / 56 and 24 / 40 / 72 one-time hours, and 2 / 4 / 8 monthly, are our own estimates and look reasonable. Adobe states no hours.
