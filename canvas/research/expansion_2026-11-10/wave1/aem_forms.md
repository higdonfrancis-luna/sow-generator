## Product: AEM Forms (`aemforms`)

Name in the tool: AEM Forms. Title: Experience Manager Forms as a Cloud Service.

What: A cloud-native service to create, manage, publish and update complex digital forms and send the submitted data to back-end systems, with APIs that generate documents from templates and data. (Experience League: Introduction to AEM Forms as a Cloud Service, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/forms-overview/home)

Adobe's sentence behind it: "Adobe Experience Manager Forms as a Cloud Service offers a cloud-native, Platform as a Service (PaaS) solution for businesses to create, manage, publish, and update complex digital forms while integrating submitted data with back-end processes" (Experience League: Introduction to AEM Forms as a Cloud Service, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/forms-overview/home)

Notes: Adobe recommends Adaptive Forms Core Components for new forms, and these lines assume them. The service keeps no submitted data in AEM: every form sends its data to a store your client owns, and AEM workflows run on Author only. Document generation (the Communications APIs) is its own add-on that Adobe enables on request, licensed by Document Renditions, and one API call or batch takes one template. The Automated Forms Conversion service produces Foundation Components forms, and the in-form Acrobat Sign fields are documented for Foundation Components only, so AF08 signs through a workflow step. Acrobat Sign and Adobe Analytics are not products in the tool, so e-signature (AF08) and form analytics (AF09) are product lines with an ext. Adobe's pages disagree with each other on XFA-based adaptive forms, HTML5 Forms and document security on the Cloud Service; see left_out and the research trail before quoting any of them. Hours are our own estimates for a mid-market client; Adobe publishes none.

### Prerequisites for the product

- An AEM as a Cloud Service program with the Forms solution switched on in Cloud Manager (Solutions & Add-ons) and the build pipeline run afterwards.
  - Quote: "After the build pipeline succeeds, selected solution is enabled for your environment." (Experience League: Onboard to AEM Forms as a Cloud Service, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/setup-configure-migrate/setup-forms-cloud-service)
- An AEM Forms license sized in Form Submissions per year (adaptive forms) or Document Renditions per year (document generation).
  - Quote: "Customer may use up to the number of Form Submissions authorized in the Sales Order." (Adobe: Adobe Experience Manager as a Cloud Service product description, https://helpx.adobe.com/legal/product-descriptions/aem-cloud-service.html)
- For document generation: the Renditions entitlement, since a Submissions license does not include Document Rendition features.
  - Quote: "Customer's license to AEM Forms Submissions does not include a license to use Document Rendition features and functionality" (Adobe: Adobe Experience Manager as a Cloud Service product description, https://helpx.adobe.com/legal/product-descriptions/aem-cloud-service.html)
- A data store your client owns for submitted data (database, REST service, SharePoint, Azure Blob Storage and similar), because no submit action stores data in AEM.
  - Quote: "The service includes no submit actions that store data to Adobe Experience Manager Cloud Service instances" (Experience League: Difference between AEM 6.5 Forms and AEM Forms as a Cloud Service, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/forms-overview/notable-changes)
- Users added to the Forms groups on Author and Publish, such as forms-users, template-authors, fdm-authors and workflow-editors.
  - Quote: "Once you setup AEM Forms as a Cloud Service, the groups listed in the below table, such as forms-users and forms-power-user, are automatically available for assignment" (Experience League: Groups and permissions, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/setup-configure-migrate/forms-groups-privileges-tasks)
- Up to 20 concurrent users on Author with a license up to 750,000 Form Submissions a year (40 at 750,000 or more).
  - Quote: "up to 20 Concurrent Users with AEM Forms licensed up to 750,000 Form Submissions per year" (Adobe: Adobe Experience Manager as a Cloud Service product description, https://helpx.adobe.com/legal/product-descriptions/aem-cloud-service.html)
- One production, one stage, one development and one rapid development environment in the base package.
  - Quote: "Customer may deploy 1 Production Environment, 1 Stage Environment, 1 Development Environment, and 1 Rapid Development Environment, all sharing the same code repository." (Adobe: Adobe Experience Manager as a Cloud Service product description, https://helpx.adobe.com/legal/product-descriptions/aem-cloud-service.html)

### Tiers and add-ons

Adobe uses two vocabularies. Experience League and Cloud Manager say Forms - Digital Enrollment and Forms - Communications; the product description sells Submissions and Renditions. We read Digital Enrollment as the Submissions package and Communications as the Renditions package, but no Adobe page states that mapping in one place (see Open questions).

- **Forms - Digital Enrollment**: The Cloud Manager solution option that switches on adaptive forms. Lines AF01 to AF11 and AF16 to AF17 assume it.
  - Quote: "You can use Forms as a Cloud Service to create an adaptive form (Digital Enrollment) or generate a customer communication." (Experience League: Onboard to AEM Forms as a Cloud Service, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/setup-configure-migrate/setup-forms-cloud-service)
- **Forms - Communications (shown as Forms - Communications Add-On where Digital Enrollment is already on)**: The Cloud Manager option that switches on the Communications APIs for document generation and manipulation, on its own or added to Digital Enrollment. Adobe enables access on request. Lines AF12 to AF15 need it.
  - Quote: "Communications capability is available as a standalone and add-on module for Forms as a Cloud Service users." (Experience League: AEM Forms as a Cloud Service Communication APIs, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/using-communications/aem-forms-cloud-service-communications-introduction)
- **AEM Forms: Submissions (license)**: The base package licensed by Form Submissions per year. It does not include Document Rendition features; those need the Renditions add-on.
  - Quote: "Customer's license to AEM Forms Submissions does not include a license to use Document Rendition features and functionality, which requires purchasing the AEM Forms Additional Renditions (Document Renditions) add-on." (Adobe: Adobe Experience Manager as a Cloud Service product description, https://helpx.adobe.com/legal/product-descriptions/aem-cloud-service.html)
- **AEM Forms: Renditions (license)**: The base package licensed by Document Renditions per year. It does not include Form Submission features, and the Automated Forms Conversion service needs the Submissions add-on.
  - Quote: "Customer's license to AEM Forms Renditions does not include a license to use Form Submission features and functionality, which requires purchasing the AEM Forms Additional Submissions (Form Submissions) add-on." (Adobe: Adobe Experience Manager as a Cloud Service product description, https://helpx.adobe.com/legal/product-descriptions/aem-cloud-service.html)
- **AEM Forms: EDS Submissions Add-on to Sites**: A limited forms add-on for AEM Sites clients on Edge Delivery: 15 fields per submission, and no Forms Designer, Automated Forms Conversion, Document of Record, e-signature integrations or workflows.
  - Quote: "does not include use of AEM Forms Designer (desktop and cloud versions), Automated Forms Conversion Service, or the following extensions related to processing of submitted forms: Document of Record, e-signature integrations, and workflows" (Adobe: Adobe Experience Manager as a Cloud Service product description, https://helpx.adobe.com/legal/product-descriptions/aem-cloud-service.html)

Also from the product description:

- A Submissions license includes Documents of Record up to twice the licensed submissions: "Customer may use, on average, 2 Documents of Record associated with each licensed Form Submission per year" (Adobe: Adobe Experience Manager as a Cloud Service product description, https://helpx.adobe.com/legal/product-descriptions/aem-cloud-service.html)
- A Renditions-only license does not include the conversion service: "Customer may not access and use Automated Forms Conversion Service without purchasing the "AEM Forms Submissions Add-on to Renditions" add-on." (Adobe: Adobe Experience Manager as a Cloud Service product description, https://helpx.adobe.com/legal/product-descriptions/aem-cloud-service.html)
- Forms Designer comes with the license: "Customer may access and use copies of AEM Forms Designer on desktop or laptop Computers only in conjunction with AEM Forms." (Adobe: Adobe Experience Manager as a Cloud Service product description, https://helpx.adobe.com/legal/product-descriptions/aem-cloud-service.html)

### Lines

- **AF01 Forms onboarding, project setup and access**: one-time, 24 / 48 / 96 hours. Enable the Forms solution on your client's Cloud Manager program (Forms - Digital Enrollment, plus the Communications add-on where documents are generated), run the build pipeline, add users to the Forms groups on Author and Publish, and set up the local SDK and the Archetype project developers deploy from.
  - Quote: "After completing Onboarding to the Adobe Experience Manager as a Cloud Service, perform the following actions to enable Forms - Digital Enrollment or Customer Communications features" (Experience League: Onboard to AEM Forms as a Cloud Service, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/setup-configure-migrate/setup-forms-cloud-service)
- **AF02 Form templates, themes and fragments**: one-time, 40 / 80 / 160 hours. Build the Adaptive Form templates, the theme that carries your client's brand and the reusable fragments (such as name and address panels) that every form starts from, on Core Components.
  - Quote: "With Template Editor, you can create a template that contains basic structure and initial content that authors can use to create forms." (Experience League: Build an Adaptive Form template with Core Components, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/adaptive-forms-authoring/authoring-adaptive-forms-core-components/create-an-adaptive-form-on-forms-cs/template-editor-core-components)
- **AF03 Adaptive form build with rules**: one-time, 80 / 160 / 320 hours. Build your client's first adaptive forms on Core Components (as a guide, one long multi-step application or about five short forms): panels and steps, fields, validation, and the rules that show, hide, calculate and call services.
  - Quote: "AEM Forms' form builder lets you create forms that are engaging, responsive, dynamic, and adaptive." (Experience League: Form builder: Create forms with core components, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/adaptive-forms-authoring/authoring-adaptive-forms-core-components/create-an-adaptive-form-on-forms-cs/creating-adaptive-form-core-components)
- **AF04 Form Data Model for back-end systems**: one-time, 40 / 80 / 160 hours. Configure your client's data sources (REST, SOAP or OData services, or a relational database) and build the Form Data Model that prefills forms from the case or records system and writes submitted data back to it.
  - Quote: "AEM Forms Data Integration allows configuring and connecting disparate data sources with AEM Forms." (Experience League: Connect AEM Forms to a database, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/integrate/use-form-data-model/data-integration)
- **AF05 Submit actions and server-side validation**: one-time, 16 / 32 / 64 hours. Set each form's submit action (REST endpoint, Form Data Model, email, SharePoint, Azure Blob Storage or an AEM workflow) so data lands in a store your client owns, add a custom submit action where needed, and turn on server-side revalidation.
  - Quote: "A submit action is triggered when a user clicks the Submit button on an Adaptive Form. Forms as a Cloud Service provides several submit actions out of the box." (Experience League: Submit Actions Supported by Adaptive Forms, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/integrate/set-submit-action/aem-forms-submit-action)
- **AF06 Submission PDF for each form**: one-time, 16 / 32 / 64 hours. Set up the Submission PDF (Document of Record) that keeps a print-friendly record of each submitted form: auto-generated, or on a branded XDP template built in Forms Designer and bound to the form's fields.
  - Quote: "To create a Submission PDF, an XFA or Acroform based template is merged with data collected via an adaptive form." (Experience League: Generate a Submission PDF (Document of Record) for Adaptive Forms (Core Components), https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/adaptive-forms-authoring/authoring-adaptive-forms-core-components/create-an-adaptive-form-on-forms-cs/generate-document-of-record-core-components)
- **AF07 Review and approval workflows** (optional): one-time, 40 / 80 / 160 hours. Build the AEM Workflow models that start when a form is submitted: assign review tasks to people or groups in the AEM Inbox, route approvals and rejections, send email notifications, and keep sensitive workflow data in your client's own storage.
  - Quote: "The assign task step creates a work item and assigns it to a user or group."   - Quote: "Adobe Acrobat Sign enables e-signature workflows for Adaptive Forms and AEM Workflows."   - Quote: "Synchronous APIs are suitable for on-demand, low latency, and single record document generation scenarios."   - Quote: "Communication APIs use customer owned Microsoft Azure Cloud storage to fetch customer records and store generated documents."   - Quote: "You can use the APIs to convert a PDF document to a PDF/A-compliant document and also to determine whether a PDF document is PDF/A-compliant." ## What surprised us, or what a partner would get wrong

1. **Submissions are never stored in AEM.** A partner used to AEM 6.5 will look for a submissions store. There is none: every form needs a destination your client owns, and the Forms Portal keeps no metadata either.
   - "The service includes no submit actions that store data to Adobe Experience Manager Cloud Service instances" (Experience League: Difference between AEM 6.5 Forms and AEM Forms as a Cloud Service, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/forms-overview/notable-changes)
   - "Data captured via forms is sent directly to configured data stores." (Experience League: Difference between AEM 6.5 Forms and AEM Forms as a Cloud Service, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/forms-overview/notable-changes)
   - "The service does not retain metadata for drafts and submitted Adaptive Forms." (Experience League: Difference between AEM 6.5 Forms and AEM Forms as a Cloud Service, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/forms-overview/notable-changes)
2. **The Forms Portal needs AEM Sites pages, Azure Storage and sign-in.** A "customer portal" is not a switch. Drafts and submissions only work with your client's Azure Storage account, and only for signed-in people.
   - "Configuring Azure Storage and the Unified Storage Connector is required because the component cannot persist or retrieve draft and submitted form data without a designated, connected storage location." (Experience League: Save forms as drafts and list them on Sites page, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/adaptive-forms-authoring/authoring-adaptive-forms-core-components/create-an-adaptive-form-on-forms-cs/introduction-to-forms-portal/save-core-component-based-form-as-draft)
   - "Only logged-in users can edit their drafts or view their submitted forms." (Experience League: Save forms as drafts and list them on Sites page, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/adaptive-forms-authoring/authoring-adaptive-forms-core-components/create-an-adaptive-form-on-forms-cs/introduction-to-forms-portal/save-core-component-based-form-as-draft)
3. **Automated conversion gives Foundation Components forms, the older kind.** Adobe recommends Core Components for new forms, yet the documented conversion produces Foundation Components forms, and the Review and Correct editor does not work on Core Components output.
   - "The above conversion settings apply to converting PDF forms to Foundation Components-based adaptive forms." (Experience League: Convert PDF forms to adaptive forms, https://experienceleague.adobe.com/en/docs/aem-forms-automated-conversion-service/using/convert-existing-forms-to-adaptive-forms)

(Experience League: Form builder: Create forms with core components, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/adaptive-forms-authoring/authoring-adaptive-forms-core-components/create-an-adaptive-form-on-forms-cs/creating-adaptive-form-core-components)
4. **The conversion service has tight limits.** Small batches only, six languages, and no scanned, colored or filled forms.
   - "Keep the number of forms in a folder less than 15 and keep the total number of pages in a folder less than 50." (Experience League: Convert PDF forms to adaptive forms, https://experienceleague.adobe.com/en/docs/aem-forms-automated-conversion-service/using/convert-existing-forms-to-adaptive-forms)
   - "Do not upload scanned, colored, filled forms, and forms in any language other than English, French, German, Spanish, Italian, and Portuguese." (Experience League: Automated Forms Conversion service (AFCS), https://experienceleague.adobe.com/en/docs/aem-forms-automated-conversion-service/using/introduction)
5. **Document generation is a separate add-on that Adobe switches on, and it is licensed differently.** A forms license does not cover letters and documents. Communications is requested through Adobe, and the product description sells it as Document Renditions.

   - "In a single API call or batch, you can use only one template with multiple DATA XML files." (Experience League: Difference between AEM 6.5 Forms and AEM Forms as a Cloud Service, https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/forms/forms-overview/notable-changes)
