## Join paid media data with web data 

Last update: October 29, 2026 

- Topics: 

- Use Cases 

CREATED FOR: 

- Admin 

This use case guide illustrates how you can join paid media summary data with website behavioral event data in Adobe Customer Journey Analytics. 

Connecting your ad accounts (Meta, Google Ads, and others) to Experience Platform provides paid media summary data in Customer Journey Analytics: daily impressions, clicks, spend, and ad-network-reported conversions per account, campaign, ad group, ad, experience, and asset. Using Customer Journey Analytics, you collect your own on-site behavioral event data with the Web SDK: page views, orders, revenue. 

When you join the two types of data in a single Workspace freeform table you can compare advertising performance with activity on your website. Use shared campaign, ad group, and ad IDs to report on impressions, clicks, and spend alongside paid landings, orders, and revenue in Analysis Workspace. 

Data source 

Example metrics 

Paid media summary data 

Impressions, clicks, spend, conversions, and conversion value reported by the ad network. 

Website behavioral events 

Paid landing pages, page views, orders, and revenue measured on your website 

Calculated metrics 

Landing page rate, web conversion rate, web return on ad spend, cost per web order, and network-versus-web conversion gap 

The combination of these two types of data allows you to compare pre-click data (from your ads) and post-click data (from your website). 

This guide covers scenarios based on connections managed by Adobe Content Analytics configurations and connections that you configure yourself. 

## How it works 

The diagram below illustrates how paid media summary data and website behavioral event data are ingested through a Customer Journey Analytics connection. 

The data view is responsible for parsing and aligning the data, so you can use Workspace to report properly on the data. 

 {modal="regular"}

Paid media summary datasets contain daily metrics without a person ID. Website event datasets contain timestamped behavioral events and a person identifier. A summary data group associates dimensions from these datasets so that equal dimension values appear in the same reporting row. 

 IMPORTANT 

This join aligns aggregated summary data and web events for reporting. It does not link an ad impression or click to an individual person. Ad-network conversions retain the network’s reporting methodology. Website orders and revenue use the attribution settings that you configure in this guide. 

## Understand the reporting join 

You can join only at levels whose IDs appear in your landing page URLs or existing event fields. For example, campaign-only tagging supports campaign reporting, but not ad-level reporting. 

 NOTE 

Content Analytics Experience-level and asset-level joins require additional URL parameters and are outside the scope of this guide. 

See Summary data and Summary data group component settings for reference.

## Prerequisites 

Confirm that you have: 

- Customer Journey Analytics Select or higher, with access to the derived field functions used here: URL Parse , Case When , Regex Replace , and, for name enrichment, Lookup . 

- Adobe Experience Platform permissions to manage schemas, datasets, and datastreams in the target sandbox, and access to datasets and Query Service for verification. 

- Customer Journey Analytics permission to edit the target connection and data view. 

- Paid media source connectors configured in the same sandbox and ingesting summary and lookup datasets. For an example connector, see Meta Ads source . 

- Website events that capture the full landing page URL, including its query string, or equivalent fields containing the network IDs. 

## Ad tagging 

Identify the query parameters that contain your campaign, ad group, and ad IDs. Existing ID-based tagging can be used without changes to the ad platforms. 

Tagging pattern 

Campaign parameter 

Ad group parameter 

Ad parameter 

Meta IDs in the website URL 

 campaign_id={{campaign.id}} 

 adset_id={{adset.id}} 

 ad_id={{ad.id}} 

Meta IDs in UTM parameters 

 utm_campaign={{campaign.id}} 

 utm_term={{adset.id}} 

 utm_content={{ad.id}} 

Google Ads IDs in UTM parameters 

 utm_campaign={{campaignid}} 

 utm_term={{adgroupid}} 

 utm_content={{creative}} 

For Meta UTM tagging, a source value such as utm_source=fb can identify the network. For Google Ads UTM tagging, use a source value such as utm_source=google . 

Some Adobe Advertising integrations use an s_kwcid value with this layout: 

 AL!<id>!3!{creative}!{matchtype}!{placement}!{network}!{product_partition_id}!{keyword}!{campaignid}!{adgroupid}

The parsing rules later in this guide apply to this layout only. Inspect actual landing URLs before using them. 

If you do not have access to the ad platforms, inspect landing URLs in your web dataset. You can also inspect these paid media lookup fields: 

- Google Ads account lookup: additionalDetails entries named google_ads_tracking_url_template and google_ads_final_url_suffix . 

- Meta ad lookup: paidMedia.adDetails.creative.paidMediaCreative.destinationURL . 

Macros in stored destination URLs can be percent-encoded. Validate the expanded IDs in actual website events rather than assuming that a stored URL represents the final landing URL. 

 IMPORTANT 

Campaign names, such as utm_campaign=fall_sale , do not match campaign IDs. Join only at levels that contain actual IDs. If IDs are absent, work with your ad operations team to update tagging for future traffic; this setup cannot reconstruct missing IDs for historical visits.

## Configure the datastream and Web SDK 

- Go to Data Collection > Datastreams > New Datastream . 

- Name the datastream and select your event schema as the mapping schema. 

- Save, then select Add Service > Adobe Experience Platform . 

- Select the sandbox and event dataset, then Save . 

- Use the datastream ID to configure the Experience Platform Web SDK . 

Capture the following: 

- Capture a page view on each page, with the full URL in web.webPageDetails.URL and web.webPageDetails.pageViews.value set to 1 . 

- Purchase events with commerce.purchases.value set to 1 , plus commerce.order.priceTotal , commerce.order.currencyCode , and commerce.order.purchaseID . 

- A person identifier suitable for your Customer Journey Analytics connection. 

You do not need to parse UTM parameters in website code. The derived fields in this guide parse URLs at report time. If your implementation already captures the IDs in dedicated fields, use those fields instead. 

## Verify ingestion 

Check the dataset activity for successful ingestion. In Query Service, run the following query, replacing web_behavioral_events with your dataset’s SQL table name: 

 SELECT timestamp, eventType, web.webPageDetails.URL
FROM web_behavioral_events
WHERE web.webPageDetails.URL RLIKE '[?&](campaign_id|utm_campaign|s_kwcid)='
ORDER BY timestamp DESC
LIMIT 20;

Confirm that the returned URLs contain expanded network IDs. If paid traffic exists but the query returns no rows, inspect recent landing URLs and adapt the parameter pattern to your tagging.

## Create the web network derived field 

Select Create derived field and name the field PM Network (Web) . All URL Parse rules below read the website dataset’s web.webPageDetails.URL field, referred to here as Page URL. 

Add rules in this order:

Function

2 

 URL Parse 

Page URL. Get query string value for s_kwcid . 

3 

 URL Parse 

Page URL. Get query string value for gclid . 

4 

 URL Parse 

Page URL. Get query string value for fbclid . 

5 

 Case When 

Apply the conditions below. 

Configure the final Case When rule: 

- If rule 2 or rule 3 is set, return google_ads . 

- Otherwise, if rule 4 is set or rule 1 equals fb , facebook , ig , instagram , or meta , return meta . 

- Otherwise, if rule 1 equals google , return google_ads . 

- Add mappings for other networks only after confirming their values in paidMedia.adNetwork . 

- Otherwise, return no value. 

To enter a fixed output, open the value picker, select Custom String Value , and enter the string. 

These classification rules are tagging-based, not proof that a visit came from a paid ad. For example, a source parameter alone can also appear on non-paid links. Adapt the conditions to your tagging conventions before using the field as a paid traffic classifier.

The campaign expression extracts the second-to-last s_kwcid value, the ad group expression extracts the last value, and the ad expression extracts the fourth value. These positions depend on the exact layout shown earlier.

Each derived field supports up to five URL Parse rules and one Regex Replace rule . Keep one ID per derived field. 

## Create the paid landings metric 

Create a derived field named Paid Media Landings (Web) using PM Campaign ID (Web) as the input. 

The builder expands the input field’s rules into the new field. After those rules, add a Case When rule that returns the custom numeric value 1 when the campaign ID output is set, and no value otherwise. Add the result as a metric. 

This metric counts events carrying a campaign ID. This metric represents landings only when your implementation sends that ID-bearing URL on the landing event rather than on repeated or unrelated events. 

 NOTE 

Expanded derived field rules are copies. If you change an ID field, inspect and update the corresponding landing and name fields too. If you omitted parsing rules, reference the actual final ID rule rather than assuming it is rule 5.

## Build and validate the report 

- 

Create a Workspace project using the configured data view. 

- 

Choose a date range with data from both sources. Allow for paid media ingestion delays; summary data can lag website events by a day. 

- 

Add a freeform table with PM Campaign ID (Web) as the row dimension, or PM Campaign Name (Web) if you configured name groups. 

- 

Add Impressions | Ad Summary , Clicks | Ad Summary , Spend | Ad Summary , Conversions | Ad Summary , Paid Media Landings | Ad Summary , Orders (Web) , Revenue (Web) , and the calculated metrics. 

- 

Break a campaign row down by the web ad group and ad dimensions. Confirm that both summary and web metrics populate at each configured level. 

- 

Add a second table using PM Network (Web) to review network-level totals and the no-value row. 

Check the following before sharing the report: 

- Landing event IDs match Paid Media Ad Summary IDs. 

- Paid media metrics and web metrics populate on the same rows. 

- Orders and revenue receive the intended session or person attribution. 

- No-value rows are understood. They can contain unmatched summary data or web activity without paid media identifiers. 

- Landing-to-click differences are consistent with your collection setup, consent handling, and reporting windows. There is no universal expected match rate. 

## Troubleshoot mismatches 

Symptom 

Check and corrective action 

Summary metrics populate, but all web metrics are zero 

Confirm that rows use web dimensions and that groups were created on those dimensions. Then inspect landing URLs for actual IDs rather than names. 

Web metrics populate, but a summary level is empty 

Confirm that the level’s summary dimension is in the corresponding group and that matching paid media data exists for the selected dates. 

Names are missing on web rows 

Check the Lookup input and matching field in the final output preview. Use ID groups if name enrichment is unavailable. 

Web IDs contain literal or encoded macros 

Ask the ad operations team to inspect the destination URL and confirm that the network expands the macros before landing. 

Google Ads IDs do not match 

Inspect the actual s_kwcid layout or UTM parameters and update the parsing rules. 

Network values are split, such as facebook and meta 

Make the network derived field output match paidMedia.adNetwork exactly. 

An ID appears in separate rows 

Confirm that settings match across grouped dimensions and inspect the underlying string values. 

Website activity appears shifted by a day 

Compare the data view time zone with the UTC summary day boundaries. 

Orders or revenue are zero or unexpectedly low under campaigns 

Explicitly enable the metric attribution override and confirm its model, container, and lookback settings. 

Paid landings are unexpectedly high 

Confirm that only landing events carry the counted campaign parameter. Repeated ID-bearing events also contribute to this metric. 

Distinct campaigns share a name row 

Use ID-based reporting to distinguish entities that have identical names.
